# Skill: Rust Coding (Core Rust Development Guide)

This skill must be activated and followed strictly whenever writing or modifying Rust code in the `rust/` directory.

## Architectural Mandates & Decisions

### 1. Persistence, Schema & Record IDs
- **Never Use Raw String/Legacy Record Functions**: NEVER write raw `type::thing(...)` or `type::record(...)` in queries.
- **Always Bind Typed RecordIds**: Construct `surrealdb::types::RecordId::new(table_name, key)` (or `TypedRecordId::to_record_id()`) and bind it directly as a parameter:
  - `query("CREATE $id SET ...").bind(("id", record_id))`
  - `query("SELECT * FROM $id;").bind(("id", record_id))`
  - `query("UPDATE $id SET ...").bind(("id", record_id))`
  - `query("DELETE $id;").bind(("id", record_id))`
  - `query("UPSERT $id SET ...").bind(("id", record_id))`
- **Constants/Enums for Table Names**: Always declare table name constants (e.g. `const MAP_REGISTRY_TABLE: &str = "map_registry";`) or use `TableKind` enums. Never scatter loose string literals.
- **Typed Record IDs**: Represent graph record IDs using `TypedRecordId` (`TableKind` + `Uuid`), stack-allocated to exactly 17 bytes (`assert!(size_of::<TypedRecordId>() == 17)`), zero-allocation, implementing `SurrealValue` for AST `.bind()`.
- **Autogenerated Schema (SSOT)**: Do NOT manually edit `rust/src/persistence/schema.surql`. Modify Rust domain structs in `rust/src/domain/` and run the `generate-schema` binary target.
- **Transactions & Direct Patches**: Wrap cascading deletes in inline SurrealQL transactions (`BEGIN TRANSACTION ... COMMIT`) to purge orphaned relations atomically. Execute direct un-batched `UPDATE` statements for single-property patches.
- **Hard Deletes & History**: Hard-delete records directly from tables. Store Undo/Redo history separately using atomic `SymmetricEntityPatch` (forward and reverse `EntityPatch` pairs) in the `History` table.
- **Vectorized Graph Queries**: Use native `RELATE` edge statements. Execute 2-hop graph degree analysis and spatial density calculations inside SurrealDB via vectorized nested `LET` subqueries.
- **Package Archive Serialization**: Serialize `.cent` zip package metadata and graph tables as dynamic `surrealdb::types::Value` trees using `rmp_serde` MessagePack to decouple file persistence from Rust struct schema changes.

### 2. Multi-Crate Domain Synchronization
- **Zero Sibling Crate Imports in Domain**: `centrode_core/src/domain/` is the SSOT and is copied directly to `centrode_daemon/src/domain/` via `dart scripts/sync_domain.dart`. Never add crate-specific dependencies (such as `use centrode_daemon::...`) inside `domain/` modules, as it will break compilation when copied into `centrode_daemon`.
- **Cross-Crate Trait Implementations**: Keep `From`/`Into` conversions and integration bindings outside domain modules, placing them in higher-tier service or bridge modules (e.g., `bridge/api.rs`, `services/`).

### 3. IPC & Error Propagation
- **Inspect Full Anyhow Error Chains**: When checking `anyhow::Error` for connection errors (e.g. pipe missing, connection refused, broken pipe), always inspect the entire error chain with `format!("{:#}", e)`. `e.to_string()` prints ONLY the outermost context and conceals the underlying OS error (such as `os error 2`).
- **Handle Disconnected/Idle Pipe States**: When probing IPC pipes on startup (e.g. `yield_daemon_if_running()`), treat missing pipes, connection refused, broken pipe, and unexpected EOF (`failed to fill whole buffer`, `Broken pipe`, `os error 109`, `os error 232`) as "target process is not running" rather than failing the startup sequence.

### 4. FFI Bridge & Concurrency (FRB v2)
- **Zero-Trust FFI Surface**: Rebuild bindings via `flutter pub run build_runner build --delete-conflicting-outputs` whenever `rust/src/bridge/api.rs` changes.
- **Lifetime & Method Borrowing**: Enable FRB v2 lifetime borrowing (`enable_lifetime: true`) and borrow `&self` across FFI method calls.
- **Fine-Grained Enum Patches**: Transmit strongly-typed variant payloads (`NodePatch` / `RelationPatch` / `SymmetricEntityPatch`) over FFI instead of full struct replacements.
- **16ms Physics Batching**: Stream force-layout physics ticks over Tokio broadcast channels throttled at 16ms intervals (~60 FPS).
- **Synchronous Engine Mutexes**: Wrap shared engines (`RelationEngine`, `LayoutEngine`) in `std::sync::Mutex` held strictly within synchronous code blocks without `.await` points.

### 5. Algorithmic Routing & Layout Engines
- **Decoupled Routing Architecture**: Decouple path steering (`Steer` trait) from curve shaping (`Shaper` trait) via `RoutingStrategy<S, H>`. Use Rayon thread pools for parallel A* grid pathfinding with straight-line fallback.
- **AABB Wall Springs & Degree Density**: Use linear spring penalty forces for `OptArea` bounding box containment. Weight density dispersion inversely to node degree (`1 / (1 + degree)`).

### 6. Error Handling & Infrastructure
- Do NOT build custom error fallbacks. Let errors bubble up using `anyhow::Result`.
- Do NOT add database migrations.
- Use `tracing` macros (`info`, `debug`, `warn`, `error`) for telemetry. Never use `println!`.
- Decouple Rust core completely from Dart UI presentation details.

## Verification Checklist

1. Execute `cargo test --workspace` in the `rust/` directory.
2. Ensure tests run against isolated in-memory engine (`Surreal::new::<Mem>(())`).
3. Ensure zero compiler warnings (`cargo check --workspace`).
