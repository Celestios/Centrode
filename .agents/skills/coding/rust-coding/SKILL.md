# Skill: Rust Coding (Core Rust Development Guide)

This skill must be activated and followed strictly whenever writing or modifying Rust code in the `rust/` directory.

## Core Mandates

### 1. Persistence Conformity & Schema Generator
- **Do NOT manually edit the schema file** [schema.surql](rust/src/persistence/schema.surql). It is autogenerated from domain structures.
- Modify the Rust structs in [domain](rust/src/domain/) and run the schema generator.
- Make sure database models implement the proper traits, such as `SurrealTable` or `SurrealValue`.

### 2. Zero-Trust FFI Boundary (FRB v2)
- Any modification to FFI parameter signatures, types, or methods under [api.rs](rust/src/bridge/api.rs) requires rebuilding the Dart-Rust bindings.
- You must run the code generator command immediately after modifying the FFI surface:
  ```bash
  flutter pub run build_runner build --delete-conflicting-outputs
  ```
- Make sure annotations like `#[frb(sync)]` or custom serializer traits are preserved.

### 3. Error Handling & Standard Logging
- Do NOT build custom error fallbacks. Let errors bubble up using `anyhow::Result` or standard anyhow mapping.
- Do NOT add migrations.
- Use standard logging macros (`tracing::info`, `tracing::debug`, `tracing::warn`, `tracing::error`) for all traces. Do not print using `println!` in production code.

### 4. Layer Boundary Compliance
- Rust core must remain entirely decoupled from Dart UI/presentation details. It is a pure domain store and engine layer.

## Verification Checklist

1. Execute `cargo test` in the `/rust` directory before declaring changes complete.
2. Ensure tests run against the isolated in-memory configuration (`Surreal::new::<Mem>(())`).
3. Ensure no compile warnings are introduced (fix unused variables/imports).
